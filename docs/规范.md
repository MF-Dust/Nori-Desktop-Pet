## 总体原则

1. **一致优先**: 改代码前先看同目录已有文件的风格, 跟着已有风格走.
2. **本地化命名**: 业务概念用可读命名, 常量用 `UPPER_SNAKE`, 变量用 `camelCase`, 导出的方法 / 类型等用 `PascalCase` (见各端分节).
3. **模块职责单一**: 一个文件只做一件事, 类同的文件放到同一目录.
4. **不要塞大文件**: `lib.rs` / 入口文件只做装配, 业务逻辑拆到独立模块 (`commands.rs`/`config.rs`/`db.rs`/`log.rs` 等).
5. **减少魔法数字/字符串**: 可复用的常量抽出去 (如配置键 / 步骤数).
6. **解耦! 解耦! 解耦!**

---

## 通用代码风格

- **缩进用 Tab** (不是空格), 项目源码 `.ts/.vue/.rs/.less` 均为 Tab 缩进.
- **换行**: LF, Windows 下 Git 会做 CRLF 转换警告, 属正常.
- **字符串**: 前端统一双引号优先 `"`; Rust 字符串用 `"`.
- **注释**:
  - 前端用 `//` (组件内块注释同), 有导出的方法 / 类型等时, 用 `/**` 文档注释.
  - Rust 用 `///` 文档注释 (给 Tauri command 写前端调用示例), `//` 行内注释.

## 前端(Vue 3 + TypeScript + Less)

### 组件与命名

- 组件统一用 **`<script setup lang="ts">`**.
- **文件命名**: PascalCase, 如 `LanguageSelect.vue`/`LlmConnect.vue`.
- **组件放对目录**:
  - 页面级: `src/views/*.vue`
  - 向导步骤组件: `src/components/*.vue`
- 局部常量用 `UPPER_SNAKE` (如 `CONFIG_KEY`/`STEPS_COUNT`/`KEY_BASE`), 局部变量用 `camelCase`.
- 导出的方法 / 类型等用 `PascalCase`.

### 样式与单位

- 样式写在 `<style scoped lang="less">`, 使用 **Less**.
- **长度单位一律 rem**: 全局根字号在 `src/assets/style/theme.less` 设为 `62.5%` (即 `1rem = 10px`), 不要直接用 `px` 写尺寸.
- 颜色/圆角/阴影等**直接用全局 CSS 变量**(`var(--nori-*)`/`var(--bg-*)`/`var(--text-*)`/`var(--radius-*)`/`var(--line-*)`/`var(--glow-*)`/`var(--danger)` / `var(--warning)`), 定义见 `theme.less`.
- 布局: 窗口最外层写 `width/height: 100%` 或 `100vh/100vw`, 内部子层用 `flex`/`grid` 与 `100%`, **不要用 `position: absolute` 做页面布局**; 需要叠放时用 `grid-area` 重叠.
- 按钮/输入等通用形态参考已存在的 `.btn`/`.input`/`.field` 样式; hover 用青绿光晕(`--glow-teal-soft`)效果.

### 状态与数据

- 用 `ref` / `computed`(不要在 `<script setup>` 里用 `reactive` 存整个对象除非确实需要).
- 对配置项的读写统一走 `invoke("get_config"/"set_config")`(见后端/数据库节).
- 异步组件挂载里读配置用 `onMounted(async () => { ... })`, 读取失败 `console.error`, 不要把未捕获异常抛出成界面崩溃.
- 输入类配置写入用 **防抖**(参考 `LlmConnect.vue` 的 `saveOnChange`, 约 400ms), 减少频繁 invoke.
- **防抖注意**: 每个输入字段要用**相互独立的 timer**(如按 `key` 用 `Map<key, timer>` 管理), 不要多个字段共用一个 timer__否则先输入字段的定时器会被后输入字段的 `clearTimeout` 取消, 导致先输入的那份配置丢失不落库.
- 频繁输入/频繁变化的 UI 用 `v-model` 绑定 `ref`.

### 国际化(i18n)

- 文案按语言放: `src/services/i18n/locales/*.ts`.
- 读取文案统一通过 `useLanguages()`(来自 `src/services/i18n/useLanguages.ts`), 按 `components.firstRun.xxx` / `views.firstRun.xxx` 分层.
- **组件里文案要用 `computed(() => useLanguages().components.firstRun.xxx)`**, 让文案随 `locale` 响应式更新(不要做成一次性快照常量).
- 语言切换调用 `useLanguage.setLanguage(code)`(`src/services/i18n`).

### 图标

- 图标数据集中在 `src/services/icon/index.ts` 的 `icon` 对象, 用 `satisfies Record<string, IconData>`, 自动获得类型与 `IconName`/`allIcons`.
- 使用 `<Icon name="..." mode="..." class="..."/>`(`src/components/Icon.vue`, props: `name/mode/size/strokeWidth`).
- 新增图标就在 `icon` 里加一个 entry(写 `// 说明`), 也可写 `stroke` 或 `fill` 路径(24x24 viewBox).
- 图标尺寸在样式中用 rem 控制(`.btn-icon` 等), 不要散落写死像素.

### 路由与窗口

- 路由集中在 `src/router/index.ts`; `/` 默认转发到 `/init`.
- 窗口 label → 路由的映射写在 `src/App.vue` 的 `NAVIGATION`, 每个 webview 挂载后自行 `ROUTER.replace` 到对应路由.
- 窗口切显隐由 Rust 端 `complete_first_run` 控制(写 `first_run_completed` 标记 + hide/show 窗口).

## 后端(Tauri / Rust)

- **模块划分**:
  - `lib.rs`: 只做装配(`mod` 声明/插件/`setup` 初始化/`invoke_handler` 注册命令). 不要再往里塞命令.
  - `commands.rs`: 存放 `#[tauri::command]`, 每个 `pub fn` 加 `///` 文档, 注明前端 `invoke("xxx")` 的调用方式.
  - `config.rs`/`db.rs`/`log.rs`: 配置读写/数据库/日志. 再大的职责继续拆新模块.
- **命令命名**: `snake_case`, 用动词开头(`get_config`/`set_config`/`complete_first_run`/`fetch_llm_models`/`write_log`).
- **命令返回**: 一律 `Result<T, String>`(成功数/列表直接返回, 失败返回 `String` 错误信息给前端显示). 无返回用 `Result<(), String>`.
- 命令里对窗口可见性/来源校验, 白名单内才放行(参考 `complete_first_run`/`write_log` 的 `webview.label()` 检查).
- 依赖新增要克制, 确认必要再加到 `Cargo.toml`(如 HTTP 用 `reqwest`).
- 新增命令后**记得在 `lib.rs` 的 `invoke_handler` 里注册**, 否则前端调用不到.

## 配置文件与数据库

- 数据库 `config` 表的 key 用 **`snake_case`**: 如 `first_run_completed`/`selected_model`/`language`/`llm_api_base`/`llm_api_key`/`llm_model`.
- `get_config` 返回类型会因存值不同而异(字符串/数字/布尔), 前端用 `invoke<string | null>` 取字符串配置; 非字符串值注意解析.
- 首次运行完成的标记用固定 key `first_run_completed`, 统一由 `db::mark_first_run_completed` 处理.
- 新增配置键, 先在读取/写入两端(前端常量 + 后端)保持一致命名, 再落库.

---

## 提交与改动原则

- 改动尽量**聚焦**: 一个任务改相关文件即可, 不要把无关重构混进来.
- 改完跑 `npm run build`(前端 vue-tsc + vite)与 `cargo check`(后端)确保可编译.
- 不在仓库留下临时文件(如调试探针脚本/`__probe*` 等), 用完清理.
- 调试用的 `console.log` 提交前移除, 仅在有意义的报错路径保留 `console.error`.
