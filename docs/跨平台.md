# 跨平台支持矩阵

Nori 的宿主是 **Avalonia + `Avalonia.Controls.WebView`**，后者本身就是跨平台原生 WebView 抽象：Windows 用 WebView2、macOS 用 WKWebView、Linux 用 WebKitGTK。因此跳台不需要换 WebView，真正要处理的是宿主工程与 Windows-only 能力。

本次交付覆盖 **Windows / Linux / macOS 三个桌面平台**。Android head 后置，但工程结构与能力抽象已为它留好位置（`Directory.Build.props` 按 `TargetFramework` 分流，`IPlatformServices` 已是能力标志驱动）。

## 一、能力矩阵

| 能力 | Windows | Linux · X11 | Linux · Wayland | macOS |
|---|---|---|---|---|
| 前端渲染（NativeWebView） | WebView2 | WebKitGTK | WebKitGTK | WKWebView |
| 无边框 + 透明窗口 | ✅ | ✅ | ✅ | ✅ |
| 桌宠原生 OpenGL 渲染 | ✅ | ✅ | ✅ | ✅ |
| 窗口置顶 | ✅ `Topmost` | ✅ `_NET_WM_STATE_ABOVE` | ✅ | ✅ `NSFloatingWindowLevel` |
| 逐像素点击穿透 | ✅ `WM_NCHITTEST` 逐点 | ✅ `XShape` 输入形状（游程近似） | ❌ 降级：整窗可点 | ✅ `ignoresMouseEvents` 按 alpha 切换 |
| 全局光标（眼神跟随） | ✅ `GetCursorPos` | ✅ `XQueryPointer` | ❌ 降级：窗口内跟随 | ✅ `NSEvent.mouseLocation` |
| HTML 标题栏拖动窗口 | ✅ `WM_NCLBUTTONDOWN` | ✅ `_NET_WM_MOVERESIZE` | ❌ 降级：拖动手柄 | ✅ `performWindowDragWithEvent:` |
| 系统托盘 | ✅ | ⚠️ 视桌面环境 | ⚠️ 视桌面环境 | ✅ |
| TTS 播放 + 口型同步 | ✅ WebAudio | ✅ | ✅ | ✅ |
| 麦克风录音 | ✅ | ✅ | ✅ | ✅（需 `Info.plist`） |
| 密钥静态加密 | ✅ DPAPI 保护密钥文件 | ✅ libsecret / 0600 文件 | ✅ | ✅ Keychain / 0600 文件 |

图例：✅ 支持 · ⚠️ 取决于环境 · ❌ 不支持（有明确降级）

## 二、降级怎么发生

所有平台差异都收敛到 `Nori.Core/Platform/IPlatformServices.cs` 的能力标志后面，并原样进快照：

```ts
snapshot.platform = {
  os: "windows" | "macos" | "linux" | "unknown",
  sessionType: "windows" | "macos" | "x11" | "wayland" | "unknown",
  supportsGlobalCursor, supportsWindowDrag, supportsHitThrough, supportsTopmost, supportsTray,
}
```

**前端一切平台相关 UI 都由它驱动**：不支持就明确禁用并给出说明，而不是靠 `try/catch` 静默吞掉 `PlatformNotSupportedException`。

- **Wayland**：协议不提供全局光标与输入形状。`LinuxPlatformServices.Create()` 探测到纯 Wayland 会话（`XDG_SESSION_TYPE=wayland` 且没有 `DISPLAY`）时直接返回能力全 `false` 的实现，桌宠降级为「整窗可点 + 拖动手柄 + 免打扰开关」，眼神跟随退化为窗口内指针跟随。XWayland 可用（有 `DISPLAY`）时按 X11 处理，能力齐全。
- **托盘不可用**：`TrayMenu.Install` 返回 `false`，`supportsTray` 随之为 `false`，前端在主窗内提供常驻入口与退出按钮，并写日志。
- **桌宠穿透同步失败**：`PetWindow.OnHitShapeTick` 捕获 P/Invoke 异常后停掉同步定时器、保持整窗可点并记 warn，绝不打断渲染循环。

## 三、Windows-only 能力是怎么跳台的

### 音频与录音：下沉到前端

原来是 NAudio（仅 Windows）。现在：

- **播放**：TTS 字节不过 JSON 桥。`MediaExchange` 登记一次性 token，`AssetServer` 暴露 `/{prefix}/media/{token}`（GET 取走即删、2 分钟过期、`Host` 头与前缀校验照旧），宿主推 `nori:audio-play {url}`，前端 WebAudio 播放。
- **口型同步**：前端 `AnalyserNode` 每 ~60ms 算一次 RMS → `audio_level` 命令回传 → 直驱桌宠嘴型。
- **录音**：宿主推 `nori:audio-record-start {uploadUrl}`，前端 `MediaRecorder` 采集，停止时 `POST` 回同一 token。
- **音频宿主固定为 `main` 窗口**：它关窗只隐藏、进程内始终存在，所以隐藏时依然能放声。

`http://127.0.0.1:<port>` 属安全上下文，`getUserMedia` 可用。

> **待实测**：隐藏 `main` 窗口时 WebView 的音频与定时器是否被节流。WebView2 默认不挂起，但未在三平台逐一验证。若不稳定，回退方案是「播放期间临时保持窗口存活的静默前台策略」，不回退 NAudio。

> **权限钩子**：`Avalonia.Controls.WebView 12.1.0` 的 `NativeWebView` 未公开 `PermissionRequested` 一类事件（只在内部 WebView2 COM 层有）。因此麦克风授权完全交给系统原生提示：macOS 靠 `Info.plist` 的 `NSMicrophoneUsageDescription`，Linux/Windows 靠引擎默认行为。被拒绝时前端语音状态机复位并弹出可读错误。

### 密钥：可移植 AES-GCM

原来直接用 DPAPI（仅 Windows）。现在配置里的敏感字段统一用 **AES-256-GCM**（格式 `nsec1:<base64(nonce|ciphertext|tag)>`），主密钥交给平台密钥库：

| 平台 | 主密钥落点 |
|---|---|
| Windows | DPAPI(CurrentUser) 保护的 `data/secret.key` |
| macOS | Keychain（`security add/find-generic-password`），失败回退 0600 文件 |
| Linux | libsecret（`secret-tool`），失败回退 0600 文件 |

**兼容与迁移**：读到旧的 `enc:dpapi:` 值时，Windows 上解密成功后可经 `ConfigStore.UpgradeSecretFormat` 惰性重写为新格式；非 Windows 上无法解密，`ConfigStore.IsUnreadableSecret` 判为「需要重填」，由 UI 引导用户重新输入该项密钥——**绝不静默清空其他配置**。

**安全边界**：本机静态加密只防「`nori.db` 被单独拷走」，不防同一用户下的其他进程——那种场景下攻击者本来就能读到密钥文件。

## 四、数据目录（不得漂移）

必须与 Tauri 版 `app_data_dir()` 完全一致，否则老用户的 `nori.db` 与本地模型等于「凭空消失」。由 `Nori.Core.Tests/AppPathsTests.cs` 锁定。

| 平台 | 路径 |
|---|---|
| Windows | `%APPDATA%/cn.erhio.noriDesktopPet/data` |
| macOS | `~/Library/Application Support/cn.erhio.noriDesktopPet/data` |
| Linux | `$XDG_DATA_HOME/cn.erhio.noriDesktopPet/data`（缺省 `~/.local/share/...`） |

macOS 需要特判：.NET 的 `SpecialFolder.ApplicationData` 在 macOS 上是 `~/.config`，与 Tauri 不同。

## 五、构建与发布

```bash
# Windows
./publish.bat                      # win-x64

# Linux / macOS
./publish.sh                       # 按当前系统推断 RID
./publish.sh linux-x64
./publish.sh osx-arm64 osx-x64
```

本地脚本默认 framework-dependent（不打包 .NET 运行时），与现状一致。GitHub Actions 已改为手动触发，`build.yml` 与 `release.yml` 都提供 `include_runtime`：

- `false`：framework-dependent，目标机需要 .NET 10 Runtime。
- `true`：self-contained，把 .NET Runtime 一起打入包，目标机不需要预装 .NET Runtime。

两种模式都不会改变 WebView2/WebKitGTK、Live2D Cubism Core 等系统/原生依赖要求。正式发布的 `release.yml` 使用已存在的 `v<major>.<minor>.<patch>` 标签，三平台复用同一份前端 `dist`，产物名包含版本、RID 和 Runtime 模式。

产物：

- **macOS**：`.app` bundle + `Info.plist`（含 `NSMicrophoneUsageDescription`）
- **Linux**：`tar.gz` + `.desktop` 模板（`Exec` 用 `/opt/nori` 占位，安装时替换）

### 原生依赖

| 平台 | 运行期依赖 | 缺失表现 |
|---|---|---|
| Windows | Microsoft Edge WebView2 Runtime | 启动时明确报错并给安装提示 |
| Linux | `libwebkit2gtk-4.1-0`、`libgtk-3-0`（穿透还需 `libXext`） | 同上；`libXext` 缺失时穿透降级 |
| macOS | 系统自带 WebKit | — |

Cubism Core 原生库按 RID 打包，缺文件时 **MSBuild 构建期报错**（`NoriCheckCubismCore` target），而不是运行期 `DllNotFoundException`：

| RID | 文件 |
|---|---|
| win-x64 | `Live2D/native/win-x64/Live2DCubismCore.dll` |
| linux-x64 | `Live2D/native/linux-x64/libLive2DCubismCore.so` |
| linux-arm64 | `Live2D/native/linux-arm64/libLive2DCubismCore.so`（官方 SDK 未提供，需自备） |
| osx-x64 / osx-arm64 | `Live2D/native/macos/libLive2DCubismCore.dylib` |

CI（`.github/workflows/build.yml`）在 `windows-latest` / `ubuntu-latest` / `macos-14` 三平台跑完整四道门，并做发布冒烟。

## 六、已知风险

- **Avalonia Accelerate 授权**：`Avalonia.Controls.WebView` 是商业组件，其授权条款与本仓库 GPL-3.0 分发的兼容性**需项目方确认**。若不可接受，唯一等效替代是换 Tauri v2 + C# sidecar，届时宿主部分需整体重做。
- **Linux 嵌入式 WebKitGTK 可能不可用**（包 README 明确提到该场景）：兜底是用 `NativeWebDialog` 顶层窗口承载主界面（无边框/透明可能失效，属已知降级）。启动探测失败时会写日志。
- **macOS / Linux 原生 P/Invoke**：`objc_msgSend` 的变参签名（按返回类型分别声明）与 X11 事件结构体布局是易错点。全部走 UI 线程，失败时按能力标志降级，不允许抛异常打断桌宠。
- **Cubism Core 的 macOS/Linux 原生库许可与随包分发方式**需确认。
